# hail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-input website that answers `A downtown 14th st` with the next two arrivals, fetching MTA data only on request.

**Architecture:** One Bun process. Pure modules (normalize, parse, match, arrivals extraction, render) are unit-tested offline; `feed.ts` does the only network I/O with a 20s per-feed cache and 3s timeout; `server.ts` wires them together.

**Tech Stack:** Bun 1.3, TypeScript, `gtfs-realtime-bindings`.

**Spec:** `docs/superpowers/specs/2026-09-29-hail-design.md`

## Global Constraints

- One runtime dependency: `gtfs-realtime-bindings`.
- No background timers or polling; MTA fetched only while handling a request.
- Page works with JS disabled; `/?q=...` is the canonical, bookmarkable URL.
- Bind `127.0.0.1`, port from `PORT` (default 3000).
- Feed timeout 3s; cache TTL 20s; stale threshold 120s; `now` below 30s.

## Findings from real data (amend spec)

- `data/stations.csv` columns used: `GTFS Stop ID`, `Stop Name`, `Daytime Routes`, `North Direction Label`, `South Direction Label`, `Borough`.
- Labels are short (`Uptown`, `Downtown`, `Manhattan`, `Bay Ridge`), not `Downtown & Brooklyn`.
- CSV route `S` = three shuttles (feed route ids `GS`, `FS`, `H`); CSV `SIR` = feed `SI`/`SS`; feeds also carry express ids `6X`, `7X`, `FX`.
- Stop ids in feeds are `<GTFS Stop ID><N|S>`; times are protobuf Longs (use `Number()`).

## Review Focus

1. Stop names containing direction-ish words (`E queens plaza`, `2 bronx park east`, `F av n`): the word must stay part of the stop when that matches better.
2. Numeric stops (`A 14` vs `145 St`, `1 125`): numbers match exactly, never by prefix.
3. User input reflected in HTML (`<script>` in `q`): always escaped.
4. Night-only stops (A local stops at 3am are not in `Daytime Routes`): fall back to all stations when the line's own stations match poorly.
5. Shuttle/express aliases (`S 42`, `6 x`, `7`): `S` maps to `GS/FS/H` across three feeds; `6` includes `6X`.

### Task 1: Normalize + stations loader

**Files:** Create `src/normalize.ts`, `src/stations.ts`; Test `test/normalize.test.ts`, `test/stations.test.ts`

**Produces:**
- `normalize(s: string): string[]` - lowercase, `&`->`and`, split on space/`-`/`/`, strip punctuation, ordinals (`14th`->`14`), aliases (`street`->`st`, `avenue|ave`->`av`, `square`->`sq`, `place`->`pl`, `boulevard`->`blvd`, `parkway`->`pkwy`, `road`->`rd`, `heights`->`hts`, `junction`->`jct`, `west`->`w`, `east`->`e`).
- `type Station = { stopId: string; name: string; routes: string[]; northLabel: string; southLabel: string; tokens: string[] }`
- `loadStations(csvText: string): Station[]`, `stations: Station[]` (loaded from `data/stations.csv` at import), `stationsOnLine(line: string, all?: Station[]): Station[]`, `knownLines: Set<string>`.

Tests: `normalize("125th Street")` -> `["125","st"]`; `normalize("14 St-Union Sq")` -> `["14","st","union","sq"]`; `normalize("W 4 St-Wash Sq")` -> `["w","4","st","wash","sq"]`; `normalize("West 4th")` -> `["w","4"]`. Loader: A31 has routes `A C E`, name `14 St`, labels `Uptown`/`Downtown`; `stationsOnLine("A")` includes A31 and excludes 132.

### Task 2: Parse

**Files:** Create `src/parse.ts`; Test `test/parse.test.ts`

**Consumes:** `knownLines`.
**Produces:**
- `type Dir = "N" | "S"`; `type DirWord = { dir: Dir } | { borough: string }`
- `type Parsed = { ok: true; line: string; variants: { dir: DirWord | null; stopText: string }[] } | { ok: false; slot: "line" | "stop"; message: string }`
- `parse(q: string): Parsed`

Rules: first token is the line (uppercased; `SI`/`SIR` -> `SIR`; `6X` -> `6`, `7X` -> `7`, `FX` -> `F`). Unknown -> `{slot:"line", message:'line "X" not found'}`. Direction candidates only in the DIR slot (token 2) or the final token. Words: N = `up uptown north n nb northbound`; S = `down downtown south s sb southbound`; borough = `bronx brooklyn queens manhattan`. Single letters `n`/`s` only at token 2. Variants: if a direction candidate exists and removing it leaves >=1 token, emit `[withDir, withoutDir]`; else `[withoutDir]`. Empty stop -> `{slot:"stop", message:"missing stop"}`.

Tests: `A downtown 14th st` -> line A, first variant dir S, stopText `14th st`; `A 14th st downtown` same; `E queens plaza` -> variants include `{dir:null, stopText:"queens plaza"}`; `F av n` -> `n` not consumed (not at token 2... it is last token, single letter -> not consumed); `X 14` -> line error; `A` -> stop error; `6x 51` -> line 6.

### Task 3: Match

**Files:** Create `src/match.ts`; Test `test/match.test.ts`

**Consumes:** `normalize`, `Station`, `stationsOnLine`, `stations`.
**Produces:** `score(query: string[], station: string[]): number` (0..1), `findStop(line: string, stopText: string): { station: Station; score: number; also: Station[] } | null`, `MIN_SCORE = 0.5`.

Scoring: per query token best match over station tokens: exact 1; station token startsWith query token (non-numeric, query len>=2) 0.85; Levenshtein<=1 (len>=4) or <=2 (len>=7), non-numeric, 0.7; else 0. `recall = sum/qn`, `precision = matchedStationTokens/sn`, `score = 0.8*recall + 0.2*precision`. Search the line's stations; if best < MIN_SCORE, search all stations. `also`: other stations within 0.02 of best with different names (max 3).

Tests (query table, line -> expected stopId): `A 14th st`->A31, `A 14`->A31, `A 145`->A12, `A w 4`->A32, `A west 4th`->A32, `A canl`->A34, `A fultn`->A38, `1 times sq`->127, `L union sq`->L03, `E queens plaza`->G21, `A qwerty` -> null.

### Task 4: Arrivals extraction + feed fetch

**Files:** Create `src/feed.ts`; Test `test/feed.test.ts` using `test/fixtures/gtfs-ace.pb`

**Produces:**
- `feedsFor(line: string): string[]` (paths like `gtfs-ace`), `routeIdsFor(line: string): Set<string>`
- `type Arrival = { dir: Dir; route: string; secs: number }`
- `extractArrivals(msg: FeedMessage, routeIds: Set<string>, stopId: string, now: number): Arrival[]` - sorted by secs, drops `secs < -30`.
- `type FeedResult = { arrivals: Arrival[]; ageSecs: number }`
- `getArrivals(line: string, stopId: string, now?: number): Promise<FeedResult>` - fetches all feeds for the line (cached 20s, 3s timeout), merges, ageSecs = now - oldest header timestamp. Throws `FeedError` on failure.

Tests: fixture with `now` = header timestamp: A arrivals at A31 exist in both N and S, sorted ascending, all route `A`; routeIds for `S` = `GS FS H`; `6` includes `6X`; `feedsFor("S")` has three feeds.

### Task 5: Render

**Files:** Create `src/render.ts`; Test `test/render.test.ts`

**Produces:** `type Answer = { kind: "ok"; station: Station; also: Station[]; groups: { dir: Dir; label: string; arrivals: Arrival[] }[]; ageSecs: number; line: string } | { kind: "error"; slot: "line" | "stop" | null; message: string }`; `fmtMins(secs: number): string`; `renderAnswer(a: Answer): string`; `renderPage(q: string, a: Answer | null): string`.

Tests: `fmtMins(20)`=`now`, `fmtMins(89)`=`1 min`, `fmtMins(600)`=`10 min`; `renderPage('<script>', null)` contains `&lt;script&gt;` and not `<script>alert`; error with slot `line` marks the LINE hint as active; stale answer (`ageSecs` 180) shows `data 3m old`.

### Task 6: Server + client JS

**Files:** Create `src/answer.ts` (query -> Answer orchestration), `src/server.ts`, `src/client.js` (inlined into page); Test `test/answer.test.ts` with injected fetcher.

**Produces:** `answer(q: string, deps?: { getArrivals }): Promise<Answer>`; server `GET /` -> page, `GET /?q=` -> page with answer, `GET /?q=&partial=1` -> answer fragment only, `Cache-Control: no-store`, other paths 404.

Direction resolution: for each parse variant, run `findStop`; pick highest score (tie -> variant with direction). Borough word -> compare to station north/south labels (lowercase contains); unmatched borough -> both directions. Take first 2 arrivals per direction.

Client JS: intercept submit, fetch partial, swap `#out`, `history.replaceState` to `/?q=`; ArrowUp/ArrowDown recall last 10 queries from localStorage (try/catch).

Verify: `bun test` all green; `bun run dev`; curl `/?q=A+downtown+14th+st` returns arrivals; browser check.
